2. Architecture Scenario Suite: How Each Scenario Is Handled at Each Level

Click any scenario card below to trigger a live run. The prototype will step through Level 1 (Phone Input), Level 2 (Evaluator HSM), Level 3 (Unblinding), Level 4 (Registry & Attribution), and Level 5 (PEP Policy Enforcement).

Scenario 1 First-Time

Single Farmer, New Onboarding

Farmer registers with One Acre Fund. Blinded scalar point verified at Evaluator HSM, new Entity UUID issued, role marked as onboarder.

Scenario 2 Overlap

Cross-Provider Overlap

Same farmer registers with DigiFarm. Demonstrates that VOPRF produces the exact same token (Provider ID decoupled). No duplicate entity is created; role marked as contributor.

Scenario 3 Shared SIM

Shared Household Mobile Phone

Two household members share one phone. Demonstrates how phone-derived identity resolves to a shared pseudonymous device entity without legal person identity conflation.

Scenario 4 Number Change

Changed / Reassigned Phone

Farmer migrates to a new SIM card. Demonstrates TokenAlias rotation linking new token to the same Entity UUID while preserving historical attribution.

Scenario 5 Opt-Out & PEP

Consent Withdrawal & PEP Block

Farmer sends opt-out request. Consent transitions to WITHDRAWN. Policy Enforcement Point (PEP) immediately blocks subsequent advisory SMS dispatch (403 Forbidden).

Scenario 6 Offline Sync

Rural Store-and-Forward

Agent registers farmer with zero connectivity. Queued in local encrypted SQLite store. Synced when back online, preserving original attribution timestamp and zeroizing local storage.

Partner Registrations (Attribution)

Attribution is decoupled from identity. Provider ID is stored in the association layer, not inside the cryptographic hash input.
